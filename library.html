Glossary

Core terms, defined plainly

Every term gets a one-line definition up front, plus a longer "+ more" explanation with context and an example — pick the depth you need.

BitT01
Foundations

The smallest unit of digital information — a single 0 or 1.

Bits are the raw currency of computing — a single transistor state, a single position in memory, a single pixel's on/off value. Group eight of them together and you get a byte, which is usually the smallest unit a program actually works with day to day.

Boolean AlgebraT02
Foundations

The algebra of true/false logic that every digital circuit is ultimately built from.

Named after George Boole, this branch of algebra works with only two values — true and false — combined using operators like AND, OR, and NOT. Every digital circuit, from a single logic gate to an entire CPU, is really just boolean algebra expressed in silicon.

Logic GateT03
Foundations

A circuit that produces one boolean output from one or more boolean inputs — AND, OR, NOT, and their combinations.

A logic gate takes one or more binary inputs and produces a single binary output based on a fixed rule — an AND gate only outputs 1 if every input is 1, for example. Chain enough gates together in the right pattern and you can build anything from a calculator to a full processor.

CompilerT04
Foundations

A program that translates source code, like C, into the machine code a processor can actually run.

Writing in C or a similar language would be pointless if the processor couldn't understand it — that's the compiler's job. It parses your source code, checks it for errors, and converts it into machine instructions the CPU can execute directly, often optimizing the result along the way.

AlgorithmT05
Foundations

A finite, well-defined sequence of steps for solving a problem, independent of any one programming language.

An algorithm is language-agnostic — the same sorting algorithm can be written in C, Python, or pseudocode and still be the same algorithm underneath. What matters is that it's finite and well-defined, which is what separates it from a vague idea of how to solve something.

PointerT06
Data Structures

A variable that stores the memory address of another variable, rather than a value itself.

In C, a pointer holds an address like 0x7ffee3, not a value like 42. Dereferencing that pointer follows the address to read or write whatever's actually stored there — powerful for building linked structures, but also the source of most beginner C bugs.

ArrayT07
Data Structures

A fixed-size, contiguous block of memory holding same-type elements, accessed by index.

Because an array's elements sit next to each other in memory, the computer can jump straight to any index using simple arithmetic — no searching required. The trade-off is that its size is usually fixed once created, unlike more flexible structures such as linked lists.

StackT08
Data Structures

A last-in-first-out structure — the most recently added item is always the first one removed.

Think of a stack of plates — you can only add or remove from the top. That last-in-first-out behaviour makes stacks a natural fit for undo functionality, expression evaluation, and tracking function calls during recursion.

QueueT09
Data Structures

A first-in-first-out structure — items leave in the same order they arrived.

A queue behaves like a line at a canteen — whoever joined first gets served first. It's the structure behind task scheduling, print spoolers, and any system where fair ordering matters more than fast access.

RecursionT10
Data Structures

A function that solves a problem by calling itself on a smaller version of that same problem.

A recursive function needs a base case — a point where it stops calling itself — or it will run forever until memory runs out. Done well, recursion can turn a complicated problem like tree traversal into a few clean lines of code.

MicroprocessorT11
Computer Organization

The CPU chip that fetches, decodes, and executes instructions — but needs external memory and I/O to be useful.

A microprocessor on its own can't do much — it needs RAM to hold data, ROM to boot from, and I/O circuitry to talk to the outside world. Building a working computer around one is exactly what a computer organization lab walks you through.

MicrocontrollerT12
Computer Organization

A self-contained chip with a processor, memory, and I/O built onto one die — used for embedded control tasks.

Unlike a microprocessor, a microcontroller packs the processor, memory, and I/O pins onto a single chip, trading raw power for compactness and low cost. That's why microcontrollers run washing machines and traffic lights while microprocessors run laptops.

RegisterT13
Computer Organization

A small, extremely fast storage location inside the CPU that holds data mid-instruction.

Registers sit inside the CPU itself, not in RAM, which makes them the fastest storage a processor has access to — but there are only a handful of them. Every arithmetic operation the CPU performs works on values already loaded into registers.

Assembly LanguageT14
Computer Organization

A low-level, human-readable language that maps almost one-to-one onto a processor's own instructions.

Each line of assembly typically corresponds to one machine instruction, unlike C where one line might compile down to several. It's rarely used for full applications today, but it makes concepts like registers and the fetch-decode-execute cycle far more concrete.

BusT15
Computer Organization

The shared set of wires — data, address, and control — that carries information between CPU, memory, and peripherals.

The data bus carries the actual information, the address bus specifies where it's going, and the control bus carries the signals that coordinate the transfer. Bus width and speed are a major factor in how fast a computer can move data around internally.

Primary KeyT16
Databases

A column, or set of columns, that uniquely identifies every row in a table.

A good primary key never changes and is never null — a student roll number works, a student's name usually doesn't. Every other table that needs to reference a row does so through this key, which is what makes relational joins possible.

NormalizationT17
Databases

Structuring tables to reduce duplicated data and avoid inconsistent updates.

Normalization works through a series of 'normal forms,' each removing a specific kind of redundancy — repeating groups, partial dependencies, transitive dependencies, and so on. A fully normalized database sometimes needs more joins to answer a query, which is why real systems occasionally denormalize on purpose.

QueryT18
Databases

A request, usually written in SQL, to retrieve, insert, update, or delete data.

SQL queries follow a fairly consistent shape — SELECT what you want, FROM which table, WHERE which rows qualify. Beyond basic retrieval, queries can join multiple tables, aggregate data with functions like COUNT or SUM, and filter grouped results.

TransactionT19
Databases

A group of database operations that either all succeed together, or all fail together.

The classic example is a bank transfer — money leaving one account and arriving in another has to happen together, or not at all. Databases enforce this through ACID compliance, keeping transactions atomic, consistent, isolated, and durable even if something fails mid-way.

IndexT20
Databases

A lookup structure that speeds up searches on a table, at the cost of extra storage and slower writes.

Without an index, finding a row means scanning the whole table. An index — often a B-tree behind the scenes — lets the database jump close to the answer immediately, similar to how a book's index saves you from reading every page.

ProcessT21
Operating Systems

A running instance of a program, with its own memory space and execution state.

Open the same application twice and you get two separate processes, each with its own protected memory — one crashing shouldn't take the other down with it. The OS keeps track of every process's state, open files, and resource usage.

ThreadT22
Operating Systems

A lightweight unit of execution inside a process, sharing that process's memory with its sibling threads.

Threads within the same process share memory and open files, which makes communication between them fast but also introduces the risk of two threads modifying the same data at once — a problem operating systems courses spend real time on.

SchedulingT23
Operating Systems

How the OS decides which process or thread gets the CPU next.

With dozens of processes wanting CPU time and only a few cores available, the OS has to decide who runs when — using algorithms like round-robin, priority scheduling, or shortest-job-first. Good scheduling is what keeps a system feeling responsive under heavy load.

DeadlockT24
Operating Systems

A state where two or more processes each wait on a resource the other holds, so neither can proceed.

A classic example is two processes each holding a resource the other needs before it can release its own — neither can move forward. Operating systems either try to prevent deadlocks from forming or detect and recover from them after the fact.

KernelT25
Operating Systems

The core of the OS that manages CPU, memory, and hardware, running with the highest privilege level.

The kernel is the part of the OS that manages memory allocation, process scheduling, and hardware drivers with privileges no regular application is allowed to have. Linux, Windows, and Android are all built around a kernel of this kind.

ProtocolT26
Computer Networks

An agreed-upon set of rules that lets two systems exchange data in a way both understand.

HTTP, TCP, and IP are all protocols, each governing a different layer of how data actually gets from one machine to another. Without an agreed protocol, two systems could exchange bytes perfectly well and still have no idea what those bytes mean.

IP AddressT27
Computer Networks

A numeric label assigned to a device on a network, used to route data to it.

An IPv4 address looks like 192.168.1.1 — four numbers between 0 and 255. As the internet ran out of these, IPv6 was introduced with a vastly larger address space, though both are still in use side by side today.

RouterT28
Computer Networks

A device that forwards data packets between different networks based on their destination address.

A router reads the destination address on each packet and decides which connected network to forward it toward, essentially acting as a junction on the internet's map. Home routers do this on a small scale, connecting your devices to your ISP's larger network.

BandwidthT29
Computer Networks

The maximum rate data can travel across a connection, usually measured in bits per second.

Bandwidth is often confused with speed, but they're not quite the same thing — bandwidth is capacity, like the width of a pipe, while actual throughput also depends on latency and congestion. A high-bandwidth connection can still feel slow if latency is high.

FirewallT30
Computer Networks

A system that filters incoming and outgoing network traffic against a defined set of security rules.

A firewall inspects traffic against a rule set — block this port, allow that IP range — before deciding whether to let a packet through. It's a first line of defence, not a complete security solution on its own.

APIT31
Web & Capstone

A defined set of rules that lets one piece of software request data or services from another.

When a weather app on your phone shows today's forecast, it's almost certainly calling a weather service's API behind the scenes rather than measuring the weather itself. APIs let applications share functionality without either side needing to know how the other is built internally.

Version ControlT32
Web & Capstone

A system, like Git, that tracks code changes over time so a team can collaborate without overwriting each other's work.

Before Git-style version control, teams passed files around and often overwrote each other's work by accident. Now every change is tracked, branches let people work in parallel without interfering, and nothing is ever truly lost.

Client-Server ModelT33
Web & Capstone

An architecture where a client requests data or services and a server responds to that request.

Your browser is the client; the website you're visiting runs on a server somewhere else. Almost the entire web works this way — the client asks, the server answers — though peer-to-peer systems are a notable exception.

Responsive DesignT34
Web & Capstone

Building a page so its layout adapts cleanly across different screen sizes.

Rather than building separate sites for phones and desktops, responsive design uses flexible layouts, relative units, and media queries so one codebase adapts to whatever screen it's rendered on — from a small phone to a wide monitor.

DebuggingT35
Web & Capstone

Finding and fixing the cause of unexpected behaviour in a program.

Debugging is as much a mindset as a skill — reproducing the bug reliably, narrowing down where it happens, and forming a hypothesis before touching any code. Tools like breakpoints matter less than the discipline of not guessing randomly.
